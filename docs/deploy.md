# デプロイ (LAN の PC に置いて動かす)

[← 索引 (README)](../README.md)

## 言葉

| 言葉 | ここでの意味 |
|---|---|
| サーバーの PC | `qr-server` を起動する PC (LAN の中に置く) |
| 端末 | ページを開いて QR を読むスマホや PC (サーバーの PC とは別の機械) |
| 起動 | サーバーの PC で `qr-server` (Windows は `qr-server.exe`) を実行すること。実行している間だけサーバーになる |

サーバーの PC には何も入れなくてよい (実行ファイルだけ。インターネットも要らない)。

## 1. 動かす PC 用に作る

[機能を足す](extending.md) の「くり返しの手順」でテスト・ビルド・記録をしてから作る。
開発する PC と同じ OS なら `go build` だけでよい。違う OS 用は GOOS・GOARCH を付ける。

```bash
# Linux / Mac / WSL で
CGO_ENABLED=0 GOOS=linux GOARCH=amd64 go build -o qr-server-linux
```

```powershell
# Windows の PowerShell で (終わったら Remove-Item Env:GOOS, Env:GOARCH, Env:CGO_ENABLED)
$env:CGO_ENABLED="0"; $env:GOOS="linux"; $env:GOARCH="amd64"; go build -o qr-server-linux
```

| 動かす PC | GOOS | GOARCH | できるファイルの名前の例 |
|---|---|---|---|
| Linux (Intel・AMD) | `linux` | `amd64` | `qr-server-linux` |
| Windows (Intel・AMD) | `windows` | `amd64` | `qr-server.exe` |
| Mac (M シリーズ) | `darwin` | `arm64` | `qr-server-mac` |

**Linux 用は `CGO_ENABLED=0` を付ける。** 付けないと、作った PC の C のライブラリ (glibc) に頼る実行ファイルになり、別の Linux では動かないことがある。

## 2. 初回 (サーバーの PC に初めて置く)

1. 実行ファイルを、USB や scp でサーバーの PC の**書き込めるフォルダ**にコピーする (Windows の `C:\Program Files` の中などは不可)
2. 起動する (`./qr-server-linux`、Windows は `.\qr-server.exe`)。同じフォルダに証明書 (`qr-server.crt`・`qr-server.key`) ができる。ログに出る「開く URL」を控える
3. ファイアウォールで 8443 番を開ける (下の「ファイアウォール」)
4. 各端末で `https://<サーバーの PC の IP>:8443/` を開き、警告を「詳細」などから越える (**端末ごとに 1 回だけ**。`https://` は必ず付ける)
5. `https://<サーバーの PC の IP>:8443/api/health` の `version` が、記録したコミットと同じか確かめる

## 3. 2 回目以降 (更新する)

1. 「1. 動かす PC 用に作る」で実行ファイルを作る
2. サーバーの PC で、動いているものを Ctrl+C で止める
3. **実行ファイルだけを置き換える。** 隣の `qr-server.crt`・`qr-server.key` は残す (消すと証明書が変わり、すべての端末でまた警告が出る)
4. 起動し、`/api/health` の `version` が新しいコミットになったか確かめる。端末の側ですることは無い (警告も出ない)

## サーバーが止まる時

- 起動したウィンドウ (ターミナル・PowerShell) を閉じる、Ctrl+C を押す、PC を再起動する、のどれでも止まる
- PC を起動した時に自動で立ち上げる設定 (Linux の systemd、Windows のタスク スケジューラ など) は、まだ用意していない

## OS ごとの注意

| OS | 注意 |
|---|---|
| macOS | 特に無い |
| Linux | 別の Linux に持っていく実行ファイルは `CGO_ENABLED=0` を付けて作る (上) |
| Windows | **WSL は要らない。** PowerShell で同じコマンドが使える。実行ファイルは `qr-server.exe`、起動は `.\qr-server.exe` |

ライブラリを OS ごとに変える必要はない (OS ごとに違う部品は、3 つの OS 分が `frontend/package-lock.json` に入っていて、`npm ci` が自動で選ぶ)。
改行は `.gitattributes` で LF に揃えてあるので、Windows で編集しても差分が改行の違いで汚れない。

### Windows で WSL を使う場合

使ってもよいが、次の 3 つに気を付ける。迷ったら WSL を使わず PowerShell で作って動かす。

- WSL の中で `go build` すると、Linux 用の実行ファイルができる (Windows では動かない)
- WSL の中で起動したサーバーには、そのままでは LAN のほかの端末からつながらない (WSL2 は Windows の内側の別のネットワークにいるため)。LAN に出すサーバーは Windows で動かす
- Windows と WSL で同じ `frontend/node_modules/` を使い回さない (OS ごとに中身が違う)。それぞれで `npm ci` をする

## ファイアウォール

ほかの端末からつなぐには、サーバーの PC がそのポート (例 8443) への接続を受け付ける必要がある。

| OS | すること |
|---|---|
| Windows | 初回の起動で「Windows セキュリティの重要な警告」が出たら、「プライベート ネットワーク」を許可する |
| Linux | ファイアウォール (ufw・firewalld など) が動いていれば、そのポートを開ける (例: `sudo ufw allow 8443/tcp`) |
| macOS | 「受け入れますか」と聞かれたら許可する |

## IP アドレスと `https://`

端末からは `https://<サーバーの PC の IP アドレス>:8443/` で開く。文書に出てくる `192.168.1.10` は例で、実際の IP アドレスに置き換える。

| OS | 調べ方 |
|---|---|
| Windows | `ipconfig` の「IPv4 アドレス」 |
| macOS | `ipconfig getifaddr en0` |
| Linux | `hostname -I` |

- `qr-server` も起動した時に、開く URL をログに出す
- IP アドレスが変わると URL も証明書も合わなくなるので、サーバーの PC の IP アドレスは固定にしておくとよい (ルーターや PC の設定)
- **`https://` は必ず付ける。** 省いたり `http://` で開いたりすると、画面に `Client sent an HTTP request to an HTTPS server.` とだけ出て使えない (HTTPS で待っているサーバーに、暗号化しない通信で来たため。何も漏れはしない)。iPhone の Safari などは、`https://` を省くと http で開く

## HTTPS と証明書

### なぜ HTTPS が要るのか

ブラウザは、カメラを HTTPS のページにしか使わせない (サーバーの PC の中で `localhost` を開く時だけは HTTP でもよい)。
そのため、スマホで QR を読むには HTTPS で開く必要がある。

### 証明書が証明すること

HTTPS の証明書には、**名前 (IP アドレス・ホスト名)** と **公開鍵** が書いてある。
つないだ相手がその証明書と組の **秘密鍵** を持っていることを、ブラウザは通信の始めに確かめる。つまり証明するのは:

- 「この URL の名前 (例 192.168.1.10) でつながった相手は、この証明書の秘密鍵を持っている」こと
- 信頼している発行元 (認証局) の署名があれば、加えて「その名前の持ち主だと、発行元が確かめた」こと

**証明しないこと:** アプリの中身が安全か、どの版か、どの PC か (秘密鍵を盗まれれば、ほかの PC でも同じふりができる)。アプリの版は `/api/health` で確かめる。

### なぜ警告が出るのか

LAN の中のサーバーは、認証局に証明書を出してもらえないので、**自分で作った証明書 (自己署名)** を使う。
ブラウザから見ると「誰も身元を保証していない証明書」なので、端末のブラウザが警告を出す (「この接続ではプライバシーが保護されません」など)。サーバーの PC には何も出ない。

- 通信の暗号化は、警告が出ても効いている。警告は「身元を確かめられない」という意味
- 「詳細」→「アクセスする」などで進めば使える (カメラも使える)
- 信頼するのは端末 (のブラウザ)、信頼される対象は証明書。ブラウザは「この証明書は進んでよい」を端末ごとに覚えるので、**警告は端末ごとに出る**。証明書が変わると、また出る。ブラウザによっては、しばらく経つと (ブラウザを起動し直すと) また出る

### 証明書は自動で作る

`-cert`・`-key` を付けずに起動すると、**初回の起動で**、実行ファイルと同じフォルダに証明書を作って保存し、次からは同じものを使う (証明書を変えないので、端末の警告は初回だけで済む)。

| ファイル | 中身 |
|---|---|
| `qr-server.crt` | 証明書。端末に「信頼する」と登録する時は、このファイルを使う |
| `qr-server.key` | 秘密鍵。人に渡さない (持ち主だけが読める設定で保存する。git にも入れない) |

- 証明書には、この PC の名前・`localhost`・作った時の IP アドレスが入る。作ったことと中身は、起動した時のログに出る
- **IP アドレスが変わった時:** 起動した時に、ログで知らせる (自動では作り直さない。作り直すと、すべての端末でまた警告が出るため)。今の IP アドレスを入れるには、2 つのファイルを消して起動し直す
- **期限:** 397 日 (Apple の決まりの 398 日以内)。切れたら、起動した時に自動で作り直す (端末では、もう一度だけ警告が出る)
- 持っている証明書 (社内で発行したものなど) を使う時は、`-cert`・`-key` で渡す。この時は自動では作らない

### 警告を出さなくするには

- **社内の認証局がある時 (いちばん楽):** 情報システムの担当に、サーバーの PC の証明書を発行してもらい、それを `-cert`・`-key` に渡す。端末は社内の認証局を信頼しているので、警告は出ない
- **自動で作った証明書を使う時:** 端末ごとに、`qr-server.crt` を「信頼する」と登録すれば警告は出なくなる (登録の手順は OS や機種ごとに違う。まだ確かめていない)

## うまくいかない時 (動かす時)

| 症状 | 原因と対処 |
|---|---|
| 画面に `Client sent an HTTP request to an HTTPS server.` とだけ出る | `http://` で開いた。`https://` を付けて開き直す |
| スマホでカメラが始まらない | HTTP で開いている (`-http` を付けて起動した)。HTTPS で開く |
| ほかの端末から開けない | ファイアウォールか IP アドレスの間違い (上) |
| 起動すると `address already in use` (Windows では `Only one usage of each socket address`) | そのポートを別のプログラムが使っている。`-addr :9443` などに変える |
| 起動すると「秘密鍵を保存できない」で止まる | 実行ファイルのフォルダに書き込めない。書き込めるフォルダに置く |
| ログに「証明書に、この PC の今の IP アドレスが入っていない」 | IP アドレスが変わった。`qr-server.crt`・`qr-server.key` を消して起動し直す (端末ではもう一度警告が出る) |
| 別の Linux で実行ファイルが動かない | `CGO_ENABLED=0` を付けずに作った。付けて作り直す |
