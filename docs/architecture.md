# アーキテクチャ

[← 索引 (README)](../README.md)

## 全体の形

```
【作る時】 frontend/ ──npm run build (Vite)──▶ web/ ──go build (埋め込む)──▶ qr-server (実行ファイル 1 つ)

【使う時】 スマホ・PC のブラウザ ──HTTPS──▶ qr-server (LAN の PC)
              │  画面のファイルを受け取る (初回だけ。あとはブラウザのキャッシュ)
              └─ カメラの映像の読み取りは、ブラウザの中で行う
```

- **読み取りはブラウザの中で行う。** カメラの映像はサーバーに送らない。サーバーの仕事は、画面のファイルを配ることと API だけ
- 画面のファイルは実行ファイルの中に入っていて、HTTPS の証明書は初回の起動で自動で作るので、動かす PC に置くのは実行ファイルだけ
- 外部のサービスやインターネットにはつながない (LAN の中だけで動く)

## ファイルの役割

**サーバー (直下。Go の標準ライブラリだけ)**

| ファイル | 役割 |
|---|---|
| `main.go` | 起動オプションを読み、埋め込んだ画面を取り出し、待ち受けを始める。版を決める |
| `server.go` | 要求の受け方。「API」「画面のファイル」「共通 (ヘッダ・ログ)」の 3 節 |
| `cert.go` | HTTPS の証明書。初回の起動で作って実行ファイルの隣に保存し、次からは使い回す |
| `*_test.go` | テスト |

**画面 (`frontend/`)**

| ファイル | 役割 |
|---|---|
| `index.html` | 画面の骨組み。設定・履歴のシートのつなぎ (`aria-controls`・`data-close`) もここに書く |
| `vite.config.ts`・`tsconfig.json`・`package.json` | ビルド・型・依存の設定 |
| `public/third-party-licenses.txt` | 配る画面に入るライブラリ (zxing-wasm) のライセンス文 |
| `src/main.ts` | 部品を作ってつなぐ。設定が変わった時の動きもここ |
| `src/formats.ts` | 読む種類の表 (`FORMAT_INFO`) とプリセット (`PRESETS`) |
| `src/settings.ts` | 設定の表 (`SETTINGS`)・決まりごと (`RULES`)・保存と読み込み |
| `src/settings-view.ts` | 設定の画面 (表から作るので、普段は触らない) |
| `src/text.ts` | 画面に出す文字 |

| `src/camera.ts` | カメラを開く・止める・ライト・カメラの一覧 |

| `src/scanner/zxing.worker.ts`・`zxing-client.ts` | zxing で読む Worker (別のスレッド) と、そのやりとり |
| `src/scanner/browser.ts` | ブラウザの部品 (BarcodeDetector・Worker) を読み取りに渡す |

| `src/history.ts` / `src/results-view.ts` | 読んだ内容の記録 / 表示 (最後に読んだ内容と履歴) |

| `src/geometry.ts`・`src/dom.ts`・`src/elements.ts` | 座標と数の計算 / DOM の道具 / HTML の要素の取り出し |

## サーバー

### 起動オプション

| オプション | 既定 | 意味 |
|---|---|---|
| (なし) | — | HTTPS の :8443 で待つ。証明書は自動 |
| `-addr` | HTTPS は `:8443`、HTTP は `:8080` | 待ち受けるアドレス。`:9443` なら、この PC のすべての IP アドレスの 9443 番 |
| `-cert`・`-key` | なし | 持っている証明書と秘密鍵 (PEM) を使う (社内で発行したものなど)。この時は自動では作らない |
| `-http` | — | HTTPS ではなく HTTP で待つ (スマホのカメラは使えない) |

`./qr-server -h` で一覧が出る。起動すると、ほかの端末から開く URL をログに出す。止めるのは Ctrl+C (止める時に処理中の要求は待たない)。

### 要求の振り分け

| 要求 | 返すもの |
|---|---|
| `GET /api/health` | `{"status":"ok","version":"<git のコミット>"}`。動いているかと、どの版が動いているかの確認用 |
| `/api/` の下のそれ以外 | JSON の 404 (`{"error":"not found"}`)。方法 (GET・POST) が合わない時も 404 |
| それ以外 | 画面のファイル。無ければ 404 (フォルダの中身の一覧は見せない) |

- **キャッシュ:** `assets/` のファイルは名前に中身のハッシュが付く (Vite が付ける) ので、ブラウザに 1 年そのまま使わせる。`index.html` などは使う前に毎回確かめさせ、変わっていなければ 304 (中身を送らない)。そのための ETag は起動時に 1 回だけ計算する
- **安全のためのヘッダ:** 中身の種類を推測させない・ほかのサイトに埋め込ませない・読んだ URL を開いた時にこのページを伝えない・カメラはこのサイトだけ
- **ログ:** 要求ごとに 1 行 (方法・パス・状態・時間)。標準エラー出力に出す
- **版:** git が入った PC で `go build` すると、Go がコミットを記録するので、その先頭 7 桁 (コミットしていない変更があれば `-dirty`)。記録が無ければ `dev`

### HTTPS の証明書

- `-cert`・`-key` が無ければ、実行ファイルと同じフォルダの `qr-server.crt` (証明書)・`qr-server.key` (秘密鍵) を使う。無ければ作る (初回)
- 作る証明書: 自己署名、名前は `localhost`・この PC の名前・その時の IP アドレス、期限 397 日
- 期限が切れていたら作り直す。今の IP アドレスが入っていなければログで知らせるだけ (作り直すと、すべての端末でまた警告が出るため)
- 何を証明するか・なぜ警告が出るか・扱い方は [デプロイ](deploy.md) の「HTTPS と証明書」

## 画面

TypeScript で書き、React などの枠組みは使わない (ブラウザの DOM を直接扱う)。1 ページ (`index.html`) の上に、設定と履歴を「シート」として重ねて出す。

### 流れ

```
カメラ (camera.ts)
  └▶ 映像の画面ごとに (scan-loop.ts) ── 前の解析が終わるまで次は読まない
       └▶ 解析する画像を作る (frame.ts) ── 読む範囲・縮小
            └▶ 読み取り (scanner/) ── 内蔵 (BarcodeDetector) と zxing を並べて走らせる
                 ├▶ 記録と表示 (history.ts → results-view.ts) ── 最後に読んだ内容・履歴・振動と音
                 └▶ 枠の追跡 (tracks.ts)
画面の描画ごとに ── 枠の描画 (overlay.ts) ── 先読みした位置に枠を描く
```

### 設定

```
settings.ts の SETTINGS (表)
  └▶ SettingsStore.update ── RULES (合わせて変わる設定) を通し、保存して、変わったことを知らせる
       ├▶ settings-view.ts (設定の画面。表から作る)
       └▶ main.ts の store.subscribe (変わった時の動き)
```

- 読む種類 (`formats`) だけは表の外。プリセットは保存せず、読む種類から求める (`presetFor`)
- 保存した値は 1 つずつ確かめて読む (選択肢に無い値・型の違う値は既定に戻す)

### 読み取りの仕組み

- **内蔵 (BarcodeDetector):** Android の Chrome や Mac の Chrome にある、ブラウザ内蔵の読み取り。速い
- **zxing (zxing-wasm):** 内蔵が無い環境 (iPhone の Safari・Firefox) と、内蔵が読めない種類のための予備。C++ の zxing-cpp を WASM にしたもの
- **方式「自動」(既定):** 内蔵が読める種類は内蔵で、読めない種類だけ zxing で読む。zxing は読む種類を絞るほど速いので、必要な種類だけに絞る
- **UPC-A:** UPC-A は「先頭が 0 の 13 桁の EAN-13」と同じなので、どちらで読んでも 12 桁の UPC-A に揃える (`engines.ts`)
- **枠の先読み:** 結果が出るまでの遅れの分だけ、コードの動く速さから先の位置を予想して枠を描く (動かした時に枠が遅れない)

## ビルドで何が起きるか

`npm run build` は、型の確かめ (`tsc --noEmit`。間違いがあればここで止まる) のあと `vite build` で画面をまとめて `../web/` に出す。Vite がすること:

| すること | 理由 |
|---|---|
| TypeScript を JavaScript にする | ブラウザは TypeScript を読めない |
| 自分のコードと、ライブラリのうち使っている部分だけを 1 つにまとめる | 読み込むファイルを減らす。使っていない部分は削る |
| 小さくする (minify) | 改行や空白を除き、名前を短くする |
| ファイル名に中身のハッシュを付ける | 中身が変われば名前が変わるので、長くキャッシュさせても古いものが残らない |
| zxing の Worker と WASM を別のファイルとして出す | Worker は別のスレッドで動かすため |

配るファイルの大半は zxing の WASM (約 1 MB)。ビルドの道具 (TypeScript・Vite・vitest) とテストのファイルは入らない。
`go build` は `web/` の中身を実行ファイルに埋め込む (`.` や `_` で始まるファイルは除く)。

## 使っているもの

| 区分 | もの | ライセンス | 入れ方 |
|---|---|---|---|
| 読み取り (主) | BarcodeDetector | — | ブラウザ内蔵 |
| 読み取り (予備) | zxing-wasm (中身は zxing-cpp) | MIT / Apache-2.0 | npm |
| 画面の言語 | TypeScript | Apache-2.0 | npm (ビルドだけ) |
| 画面のビルド・テスト | Vite・vitest | MIT | npm (ビルド・テストだけ) |
| サーバー | Go の標準ライブラリ | BSD | Go に付いてくる |

- 版は `frontend/package.json` と `go.mod` を見る
- npm のパッケージは npm 公式 (registry.npmjs.org) から入れる。版と改ざん確認用のハッシュは `frontend/package-lock.json` に記録してある (`npm ci` はハッシュが合わないと止まる)
- 配る画面に入るライブラリは zxing-wasm だけ。そのライセンス文は `frontend/public/third-party-licenses.txt` (画面の設定のいちばん下からリンク)。zxing-wasm の版を上げたら、このファイルの版も直す

## テスト

| 対象 | 場所 | 確かめていること |
|---|---|---|
| 画面 | `frontend/src/**/*.test.ts` | 読む種類の名前の対応、内蔵と zxing の振り分け、UPC-A、枠の追跡と先読み、設定の読み込みと決まりごと、履歴、画面の文字、座標の計算、カメラの開き直しの重なり、Worker とのやりとり |
| サーバー | `server_test.go` | API、画面の配信 (種類・キャッシュ・304・404)、安全のためのヘッダ、起動オプション、画面が埋め込まれていること |
| 証明書 | `cert_test.go` | 初回に作って 2 回目は使い回す、期限切れで作り直す、IP アドレスが変わっても作り直さずに知らせる、壊れたファイルで止まる、実際に HTTPS でつながる |

- 計算はできるだけ「同じ入力なら同じ結果」の関数 (純粋関数) にしてあり、テストはそれを直接確かめる
- ブラウザの部品 (BarcodeDetector・Worker・localStorage・カメラ) は外から渡す形にしてあり、テストでは偽物を渡す
- 画面の見た目とカメラの実物は、テストでは確かめていない (ブラウザで確かめる)

## 変えない方がよい作り

簡単にしようとして変えると、壊れたり危なくなったりするもの。

| 作り | 理由 |
|---|---|
| 読んだ内容は `textContent` だけで入れる (`dom.ts` の `el`)。`innerHTML` を使わない | 読んだ QR の中身に HTML が入っていても、画面を乗っ取られない |
| URL は自動で開かない (「開く」を押した時だけ別のタブで) | 悪い QR を読んだだけで、危ないページに飛ばされない |
| 読み取りは前の解析が終わるまで次を読まない (`scan-loop.ts`) | 遅い端末で解析が溜まり、どんどん遅れるのを防ぐ |
| 読み取りの準備・カメラの開き直しは「後から来た方だけを使う」 | 設定を続けて変えた時に、古い準備やカメラが残らない |
| IP アドレスが変わっても証明書を作り直さない | 作り直すと、すべての端末でまた警告が出る |
| 知らない API は JSON の 404 | 画面の `index.html` を返すと、API の間違いに気付けない |
| CSS の全体の `[hidden]` の規則 | 要素ごとに `[hidden]` を書かなくても、隠したい物が確実に隠れる |
